# Средний расход арматуры — SP_test

Самостоятельная тестовая надстройка Revit. Кнопка **Средний расход арматуры** создаётся на вкладке **SP_test**, панель **Армирование**.

## Сборка и установка

Проверенная сборка: **Revit 2023 / .NET Framework 4.8, x64**. DLL собрана с установленными RevitAPI и RevitAPIUI 2023. Для разработки нужен .NET SDK с поддержкой WPF и targeting pack .NET Framework 4.8.

```powershell
dotnet build SP.ReinforcementCoeff.csproj -c Release -p:RevitVersion=2023
dotnet run --project tests/CalculationTests.csproj -c Release
```

Результат: `bin/Release/2023/net48/SP.ReinforcementCoeff.dll`.

1. Поместить DLL в `C:\RevitAddins\ReinforcementCoeff\SP.ReinforcementCoeff.dll`.
2. Поместить `SP.ReinforcementCoeff.addin` в `%APPDATA%\Autodesk\Revit\Addins\2023`.
3. Перезапустить Revit 2023. Вкладка появится при следующем запуске.

DLL самостоятельная: внешние SP_Addin.dll, CommunityToolkit и DLL Revit API копировать рядом не нужно. Все XAML-ресурсы встроены. Для других версий Revit нужна отдельная сборка против соответствующего API; конфигурации для 2025+ используют net8.0-windows, но в этой итерации проверена только версия 2023. Версия 2020 не поддерживается этим проектом.

Исходники первоначально были фрагментом SP_Addin без проекта, темы и общих сервисов. Для самостоятельной сборки добавлены собственные MVVM, ресурсы окон, совместимость ElementId и регистрация IExternalApplication. В конфигурации STANDALONE нет ограничения «только модели КР», поскольку реализация IsKrModel отсутствует в исходниках. Семейственные документы запрещены.

## Расчёт

Группа = комплект + ключ группировки. Комплект читается из ADSK_Комплект у бетона и RNF.Раздел у узлов арматуры. Пустой комплект исключается. Дополнительные фильтры применяются с логикой AND.

- По параметру: одинаковое непустое значение выбранного параметра, по умолчанию SP_ВРС_Группирование, у обоих типов элементов. Сравнение без учёта регистра, крайние пробелы удаляются. Геометрическое сопоставление не выполняется.
- По отметке: отметка извлекается из ADSK_Группирование у бетона и RNF.Марка конструкции у арматуры. Численно одинаковые отметки +11.4, +11.40, +11,400 дают один ключ. Группы без распознанной отметки только диагностируются, расход не рассчитывается.

Арматура берётся из категории «Компоненты узла». Требуются RNF.Учёт в спецификации=true и непустая RNF.Марка конструкции. Экземпляры и типы с ключевой пометкой «Каркас» исключаются. Как и в исходном плагине, фильтрации по виду нет: RNF-узлы на разных видах с одинаковыми ключами суммируются. Не следует дублировать учитываемые узлы на видах.

Масса RNF-элемента = RNF.Масса элемента × RNF.Количество элементов × количество сборок. При RNF.Тип массы=1 дополнительно умножается на RNF.Длина пм. Обязательны читаемый тип массы, положительная масса и положительное целое количество. Пустое количество сборок означает 1; нулевое, отрицательное или некорректное значение — ошибка. При погонной массе обязательна положительная длина. Параметр типа «Длина» переводится из внутренних единиц Revit в метры; параметр типа «Число» и числовой текст трактуются как метры. Числовая масса предполагается в кг, погонная — в кг/м; типизированная погонная масса переводится в кг/м.

Объём бетона — сумма положительных объёмов материалов с кодом Мтрл.КодМатериала на «20», переведённая в м³. В многослойном элементе известные небетонные материалы не входят в объём. Материал с положительным объёмом и пустым кодом вызывает ошибку группы.

Расход группы = сумма масс / сумма объёмов, кг/м³. Общий расход в сводке рассчитывается той же формулой по **успешным** группам. Группы с ошибками не входят в итог; их количество показано отдельно. Пример: 1000 кг / 10 м³ и 6000 кг / 30 м³ дают общий расход 175 кг/м³.

Ошибка массы хотя бы одного учитываемого RNF-элемента или неопределённый материал блокируют запись **всей группы**. В строке показаны причины и ID; вместо расхода стоит «—». Отсутствие арматуры тоже блокирует запись, чтобы не перезаписать существующий расход нулём. В составе арматуры ошибочный элемент доступен для перехода и имеет пояснение в имени; его нулевой вклад не является корректно рассчитанной массой.

## Запись и актуальность

Расчёт не изменяет модель. Отдельная команда записи сохраняет массу на RNF-элементах в SP_Масса арматуры на элемент и один расход группы на всех её бетонных элементах в SP_Средний расход арматуры. Параметры должны существовать и быть доступны для записи; числовые результаты не округляются до целого. Отсутствующие параметры автоматически не создаются.

Снимок привязан к исходному Document. Запись и выделение в другом документе запрещены. Любая транзакция, Undo/Redo исходного документа делает снимок устаревшим. Изменение настроек или фильтров требует нового расчёта. Проверка выполняется ещё раз внутри ExternalEvent перед записью. Одна транзакция охватывает все подготовленные записи успешных групп; при ошибке нет частично сохранённых значений. После успешной записи повторная запись требует нового расчёта.

## Проверки

- Сборка Revit 2023: без ошибок и предупреждений.
- 33 автоматические проверки: штучная и погонная масса, отсутствующая/неверная длина, количество сборок, переполнение, форматы отметок, запрет другого/изменённого/закрытого документа, освобождение обработчика событий. Для теста снимка применены минимальные заглушки событий; это не запуск Revit API.
- Оба WPF-окна загружены и отрисованы вне Revit с тестовыми данными, включая длинное сообщение ошибки.
- Расчёт и транзакции на реальной модели Revit ещё не проверены.

Проверка в Revit: сравнить известную массу/объём группы со спецификацией; проверить разные форматы одной отметки, отсутствие длины, пустой код материала, смешанный состав материалов, другой активный документ, изменение модели и Undo/Redo между расчётом и записью. Проверить отказ всей транзакции при параметре только для чтения.
